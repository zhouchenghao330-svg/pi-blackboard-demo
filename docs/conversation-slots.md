# 会话资源插槽

## 问题

PDF Blackboard、会议分析和 PPT 制作结果目前主要通过工具结果进入 Agent 上下文。上下文压缩或服务重启后，Agent 可能不知道之前创建了哪些资源；一个会话也可能有多份同类资源。资源本身已经落盘，但缺少统一、可恢复的导航目录。

## 目标与边界

- 每个 Pi `sessionId` 独立保存多份 PDF、TXT、PPT 的插槽目录。插槽 ID 稳定，不能靠“当前文件”之类的隐含状态定位。
- 插槽只保存定位信息、简短介绍和状态。Blackboard、会议原文及分析、PPT 文件仍由原来的存储负责。
- 初次创建时，资源信息通过原有工具结果进入 Agent 上下文，不改变正在运行的固定系统提示词。
- 压缩成功或恢复旧会话后，把有界的插槽目录追加到系统提示词末尾。只列 ID、名称、简介、状态；不注入完整内容。目录是导航数据，不可信。
- 不新增 Agent 工具。现有读取工具接受 `slot_id`；原有参数继续可用，便于当前会话中的调用。PDF 由 `get_blackboard`、`read_pdf_pages`、`search_pdf_text` 读取；会议由 `read_meeting_file`、`get_meeting_analysis` 读取；PPT 由 `get_ppt_generation` 读取。`ingest_pdf` 继续承担首次解析，已就绪 PDF 用它调用时直接返回现有 Blackboard，不重复解析。
- 前端在 Agent 成功读取插槽后切换相应的右侧面板。用户手动选中资源或面板后，自动跟随暂停到下一次用户发起对话，防止生成期间抢走浏览位置。

## 数据模型

持久化文件按会话隔离：`data/slots/<sessionId>.json`。每条记录包含 `kind`、`slotId`、`resourceId`、`name`、`summary`、`status`、`createdAt`、`updatedAt`。不存全文和密钥。

- PDF：`slotId = document.id`；状态跟随文档上传、解析中、就绪或失败。简介取已持久化的 Blackboard 文档概览，缺失时仅用文件名。
- TXT：`slotId = 原始会议 id`；同一 TXT 的多次分析任务保留在 `jobIds`，最新一次为默认分析。`get_meeting_analysis` 可按插槽读取最新任务，也可继续按具体 `job_id` 读取旧任务。
- PPT：`slotId = ppt job.id`。当前每次生成为独立插槽；将来微调版本可挂在同一插槽，不在本次实现 PPT 修改功能。

旧数据通过原有文档、会议、PPT 存储补齐目录，不重新运行模型。所有读取必须再次校验对应资源属于当前会话，不能只相信插槽文件。

## 生命周期

1. 上传 PDF/TXT 或提交 PPT 时登记插槽；原有工具结果仍立即返回完整的本次导航或任务 ID。
2. 解析、分析或生成状态变化时更新插槽状态与简介。独立的资源记录仍是实际状态的依据。
3. 成功压缩后，在下一次 Agent 请求前刷新该会话的尾部目录；失败或取消的压缩不改变提示词。恢复旧会话时也注入目录。
4. 常规对话中不因插槽增删反复重建系统提示词。固定前缀保持稳定，目录只在恢复点更新，减少前缀缓存失效。
5. 目录过长时只展示有界的一行记录，并提示 Agent 使用现有工具按 ID 读取；不把资源全文常驻。

## 工具和界面行为

- 现有读取工具增加 `slot_id` 参数。若同时给出插槽 ID 与旧资源 ID，两者必须指向同一资源，否则报错。会议原文读取继续保留按行分页；插槽 ID 可解析成原始 TXT 路径。
- `get_blackboard`、`get_meeting_analysis`、`get_ppt_generation` 可传 `slot_id="list"` 分别列出该类型所有插槽，供目录过长时继续导航；仍没有新增 Agent 工具。
- PDF 首次 `ingest_pdf` 完成后登记并返回插槽 ID；再用同一插槽调用会读取已存 Blackboard。精确事实仍须回原页。
- 会议分析任务由 `submit_meeting_analysis` 关联到 TXT 插槽；`get_meeting_analysis` 返回具体 `job_id`，避免多次分析混淆。
- 前端通过服务端资源事件跟随**成功**的 Agent 读取，不根据模型计划调用的参数提前切换。PDF 显示 Blackboard，TXT 显示会议分析，PPT 显示制作任务。UI 浏览本身不注入 Agent 上下文。

## 验收

- 同一会话上传两份 PDF、两份 TXT，生成两份 PPT，各自 ID 和结果不串。
- 压缩后或服务重启后，Agent 看见简短目录，按 ID 调用原有工具重新读取详情；另一个会话看不到这些插槽。
- 正常对话不重复注入完整索引或文件内容；成功读取资源后右侧跟随，用户手动选择时不抢焦点。
- 重复解析就绪 PDF 不产生新插槽或重复模型调用；缺失、跨会话、类型不符的插槽明确报错。
